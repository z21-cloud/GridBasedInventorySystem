# Grid-Based Inventory System (Tarkov-Like)

Реализация классической сеточной системы инвентаря (аналог популярной механики в Escape From Tarkov) на движке Unity с упором на Data-Driven подход, расширяемость и оптимизацию логики хранения данных.

---

## Основные возможности

* **Настраиваемая сетка (NxM Matrix):** Логика инвентаря построена на двумерной матрице регулируемого размера, что позволяет гибко изменять габариты контейнеров и сумок.
* **Система Drag & Drop:** Плавное перетаскивание предметов между ячейками сетки с динамическим отображением доступности места.
* **Вращение предметов (Rotation):** Возможность переворачивать предметы на 90 градусов для оптимизации пространства в инвентаре с автоматическим пересчетом занимаемых ячеек в матрице.
* **Разделение по типам (Item Sub-types):** Категоризация предметов с помощью строго типизированных перечислений для последующей фильтрации и кастомной логики поведения.
* **Готовность к сохранению (Save System Ready):** Структура данных предметов полностью сериализуема, что позволяет бесшовно интегрировать инвентарь с любой системой сохранений (JSON, Binary, PlayerPrefs).

---

## Архитектурные решения и паттерны

### 1. Data-Driven подход & ScriptableObjects
Все статические данные предметов (модель, иконка, базовые размеры, тип) вынесены в **ScriptableObjects**. Это разделяет тяжелые ассеты и конфигурацию от динамического состояния инвентаря в рантайме.

### 2. Паттерн Singleton
Центральный менеджер инвентаря реализован через паттерн **Singleton**, обеспечивая единую точку доступа для обработки событий UI, валидации перемещения предметов и координации между различными контейнерами лута.

### 3. Декаплинг через интерфейсы (Interfaces)
Взаимодействие между элементами инвентаря, контроллерами отображения и кастомными контейнерами построено на базе интерфейсов. Это исключает жесткую связанность кода (tight coupling) и позволяет легко добавлять новые типы хранилищ (например, ящики, трупы врагов, подсумки).

### 4. Event-Driven UI
Связь между бэкенд-логикой матрицы и графическим интерфейсом реализована через события (C# Events / Actions). Сетка инвентаря перерисовывается только при фактическом изменении данных, не нагружая игровой цикл в `Update`.

## Обзор структуры данных

### Классификация предметов (`ItemType`)
Для строгого контроля логики использования предметов (например, экипировка оружия только в соответствующий слот) используется перечисление типов:

```csharp
namespace Inventory
{
    public enum ItemType
    {
        Weapon,
        Food,
        Cloth,
        Money,
        Ammo,
        Magazine,
        Special
    }
}
```

## Модель состояния предмета (ItemData)
Класс ItemData инкапсулирует в себе всё текущее рантайм-состояние объекта в инвентаре и подготовлен для работы с системой сохранений:

```csharp
[System.Serializable]
public class ItemData
{
    public Item item;                        // Ссылка на ScriptableObject с базовыми параметрами
    public bool isRotated = false;           // Флаг поворота предмета в сетке
    public Vector2Int matrixPosition;        // Координата левого верхнего угла предмета в матрице NxM
    public Vector3 slotPoisiton = Vector3.zero; // Локальная позиция для UI-отображения
    public Panel.Type slotPanelType;         // Тип панели, в которой находится предмет
    public GameObject myLootContainer;       // Ссылка на физический контейнер (если применимо)
    public string myLootContainerId;         // Уникальный идентификатор контейнера для сейв-системы
}
```
